## 〇、实测证据缺口（v2 新章）

**本轮审查输入零实测数据**：三份依据（流程图/语义矩阵/前次报告）均为自我视角工件（设计声明与代码结构），无任何运行时测量。这带来两个直接后果：

1. **验证=复述风险**：本轮对前次结论的"复核"全部为代码级静态读（file:line 实证结构存在），不是运行时证据。"断链清零"与"TTS 串行是唯一瓶颈"两项强结论只能降格为**沿袭待实测**（见一、三）。
2. **H-3"以实播指标触发"的隐含前提断链**：合成并行化的触发条件是"实播合成排队 >5s"，但全链**没有**队列延迟/水位、TTS 吞吐、丢帧、GPU 利用率的采集机制——触发条件本身无法评估。这是比任何单一架构项都优先的基建缺口。

**实播指标采集**（队列延迟/水位、TTS 吞吐、丢帧、GPU 利用率）因此列为近期档第一条（T1 观测面补齐包的核心构成，与丢弃计数器、三报警盲区同批交付）。

**证伪标准（供实测后使用）**：
- "断链清零"证伪条件：任一配置项 UI 有渲染而后端零消费点（grep 消费点法抽查不通过）
- "TTS 是唯一瓶颈"证伪条件：实测中任一非 TTS 环节（分发/去重/队列/翻译/LLM）排队或处理时长 > TTS 合成时长

## 一、系统架构现状图景

系统为**进程/线程/队列三层模型**，与流程图 v2.9 拓扑一致（本轮代码级复核确认）：

- **进程层**：主系统进程（含 DanmakuListener 进程内托管）+ webui 前端进程 + EDTalk realtime_serve + RVC vc 服务 + fastrag server，后四者由 service_orchestrator.py `ManagedProcess` 统一托管：健康轮询、就绪判定窗口、意外退出自动重拉、连续失败 red 态（crash-loop 保护）、端口冲突归因、terminate→wait→kill 优雅关闭（service_orchestrator.py:149-350）；GPT-SoVITS 为进程内引擎注册 ServiceRegistry。
- **线程层**：平台回调→`process_data`（timer_handler.py:89-149）——系统消息直通 daemon 线程分发，六类互动消息经黑名单拦截（前置）→去重→限入窗口后逐条 `immediate-dispatch-*` 线程分发，同类型以独立锁串行（`_dispatch_locks.setdefault` CPython 原子）；LLM 调用在各分发线程内并发（无上限，见三）。
- **队列层**：两级队列（等待合成消息→待播放音频）`data_priority_insert` 统一优先级语义——`filter.priority_mapping` 18 键权重降序、编排音轨 `priority_override=500` 插队（queue_manager.py:344-355 `_entry_priority`）、999 复读专线单例、满载高优插队+驱逐最低优（净长度不变）、`flush_starved_playback_queue` 防饿死。

总评：**架构分层清晰（沿袭 v1 结论，本层为结构性事实非吞吐断言）、单源纪律（优先级表/配置矩阵/流程图守卫）已建立，治理工件密度在同规模项目中属高位**。v1 以来断链类缺陷保持清零态势（2026-10-31 当日多批次审查仍在推进收口——注意此为修复活动证据，非清零终证，见〇章证伪标准）。当前主要风险从"断链"转移到"单点串行吞吐"、"观测盲区"与**验收吞吐**（见六）。

### 不足（v2 更新）
1. **GPU 仲裁 fail-open**（v2 复核属实）：nvidia-smi 查询失败即放行（gpu_policy.py `_vram_free_gb` 返回 999.0 兜底值——与 999 复读专线无关），极端情况下训练在显存不足时误入→OOM 连带推理进程。失败模式是"放行"而非"拒绝"。
2. **config 写入无原子性**（v2 复核属实）：`/set_config` 远程端点整文件 `open('w')` 直写（frontend/main.py:1354），进程中途断电/崩溃可留半截 JSON；webui/main 双 Config 形态的"静默覆盖"约束仍靠纪律维持，无机制兜底。
3. **/set_config 暴露面（v2 新发现，High）**：frontend/main.py:1326-1364 三重叠加——①无鉴权（与 TODOS 已登记的 /sys_cmd 0.0.0.0 绑定同病）；②`config_path` 参数零校验（先读后写模式=可篡改任意**既有** JSON 文件：关黑名单/改 WEBHOOK 指向/改 TTS 服务指向）；③非原子写。叠加 login 默认值（enable=false/admin/123456，语义矩阵行 21）=默认无鉴权暴露。TODOS 2026-09-23 #6 仅登记了 /sys_cmd，本端点未单独登记——已并入 S-1 交付包（白名单锚定 config.json+鉴权+原子写一次修复三收益）。
4. **进程内托管的面**：DanmakuListener 引擎在主系统进程内，硬崩溃会带走主系统（TODOS S9 已登记隔离形态重评，商用前置）。
5. **报警观测盲区**（TODOS 已登记未实施）：伴奏线程失败仅 logger.warning（F6b）、闲时弹幕发送静默失败、编排静默窗口 busy-wait 缺打点（F6a）——直播中"无声/无字/卡画面"类故障用户可感知、系统无感知。
6. **共享态无锁**（v2 复核属实）：my_global 的 global_idle_time/last_username_list 为裸全局变量（grep 核实无 Lock），CPython GIL 下当前操作基本安全，但切片重赋值存在理论竞态窗口，且无一致性约束提示后续维护者。
7. **测试套件顺序污染（v2 新发现，Low）**：全量 pytest 实测 1 failed（tests/test_voice_profiles.py::test_atomic_write_preserves_other_sections，2026-10-31 commit 6b27c622 脏树态，146.19s），单跑通过=套件内前序测试污染状态，非产品缺陷。实测基线：**1 failed / 1875 passed / 80 skipped**（与 v1 记录的 1876 passed/80 skipped 口径一致，v1 未暴露该 flaky 序位）。

### 建议
- **S-1（扩容为交付包）**：config.save 全面原子化（写临时文件+os.replace）+ **/set_config 路径白名单锚定 config.json + 鉴权门**（v2 扩容：F-arch-1/F-sec-1 并入），一处公共函数收敛 webui/main 两进程写点；配合既有 .bak 机制形成双保险。
- **S-2**：gpu_policy 查询失败改为"重试一次→拒绝+告警"（fail-closed），训练入场的代价远低于误放行 OOM。
- **S-3**：将 F6a/F6b/闲时发送失败三盲区并入 alarm_notifier（复用既有模块开关与冷却机制），这是"常驻运行状态条"（D-1）数据源的补全。
- **S-4**：my_global 引入一把轻量锁或改用 queue/原子结构，成本极低，防多房间化演进后竞态放大。
- **S-5（v2 新增）**：test_voice_profiles 顺序污染定位与隔离（fixture 状态残留排查），恢复全量绿。

## 三、高效维

### 事实
- **消费回传驱动**：播放完成回执（EDTalk push_full 返回/builtin 完成回调/pygame 结束点三路互斥）驱动取下一条，无轮询间隔——playback_manager.py:225-244（v2 复核：report_consumed 环形回执窗+分类型累计在位，queue_manager.py:141-162，当前仅观测透出）。
- **合成串行（v2 复核属实，P3 沿袭待实测）**：message_queue_thread 单线程逐条合成（synthesis_manager.py:44 `while True` 逐条 `await my_play_voice`），无并行合成池；LLM 回复生成在各分发线程并发。
- **流式合成已落地**：gpt_sovits.stream_reply 逐段落盘即入队，首段不等全文。
- **变速零后处理**：变速迁移至 TTS 合成参数，pydub/ffmpeg 后处理链退役。
- **进程内直调**：GSV inproc 引擎免 HTTP 往返；fastrag 进程内整合。

### 不足（v2 加 scale 标注）
1. **TTS 合成是全链唯一串行点**（沿袭待实测——证伪标准见〇章）：[estimated] 单条合成 1-3s（GSV）/0.5-1s（edge），弹幕风暴 20 条/分=队列积压 20-60s；点歌长曲/切分长回复多段会放大占用。已登记 defer：助播独立合成队列（触发条件=助播合成排队 >10s，TODOS 2026-10-26 节 #5）。**触发条件本身依赖 T1 采集机制先行**（〇章）。
2. **翻译无缓存**（v2 复核属实）：my_translate.py 无任何缓存机制（grep 核实），[estimated] 同用户刷同内容/复读场景每条 100-500ms 外呼+计费+限流风险。
3. **LLM 并发无上限**（v2 复核属实）：每批消息一个分发线程直发 LLM（timer_handler.py:94/148 裸 Thread），[estimated] 风暴 10+ 并发请求可能触发平台限流反噬——熔断器只做失败计数，不做并发节流（负载整形缺位）。
4. **DB 无归档**：danmu/integral 等表持续增长，数据分析口径已限定近 5 万条，但表本身无清理/归档任务——长期直播 months 后查询变慢。
5. **EDTalk 播放同步等待**：push_full 返回=消费完成，播放循环串行等待网络+推理往返；数字人推理慢时背压传导至音频队列（有 300s 静默窗口上限兜底）。
6. **产线注册散落两处（v2 新发现，Medium）**：新增一条产线需改 3 处——ROUTE_TABLE（assistant_router.py:32 数据驱动表）+handler_names（timer_handler._dispatch 分发映射）+调用点。ROUTE_TABLE 已是数据驱动，handler_names 可并入单点注册。

### 建议
- **H-1（低垂果实）**：翻译加 LRU 缓存（键=内容+目标语言），10 行级改动覆盖复读刷屏场景。
- **H-2**：LLM 通道加并发信号量（如 max_concurrency=3）+ 队列化等待，防限流反噬；与熔断器互补（熔断=故障隔离，信号量=负载整形）；落地时验证开路状态不占信号量槽位。
- **H-3**：合成并行化评估分两档——轻档=edge-tts 消息并发预合成（纯 IO）；重档=GSV 批量推理/第二实例，需 GPU 预算联动 gpu_policy。触发条件=实播指标（依赖 T1 采集先行），避免过早优化。
- **H-4**：DB 归档任务（danmu 按月分区或 move-to-archive 表），与"DB 驱动弹幕历史查看面"（TODOS 2026-10-22 日志批次 #1，黄金位特性）合并设计。
- **H-5（v2 新增）**：产线注册单点化——handler_names 并入 ROUTE_TABLE 数据驱动表，新增产线改一处。

## 四、精准维

### 事实
- **优先级体系三层**：类型映射表（18 键）→ 编排插队 override=500 → 999 专线单例；满载四规则+插队驱逐语义经测试锚定（test_audio_playback_review.py 四示例逐行）。
- **消费回传精准匹配**：编排实例 choreo_step_id 精确匹配，未透传路径退回 type+content 归一化容差（O6/O9）；三路消费点互斥不双报。
- **入口秩序固定**：黑名单前置拦截（先于去重/限入/分发，不占窗口名额痕迹零残留）→ 去重 → 限入窗口 → 过滤链 → 关键词中枢（keyword_hub 统一判定 song/keymap/local_qa）。
- **丢段可见面**：切分消息 split_group 组绑定，四丢弃/取代点附注"第几段/共几段"。
- **变量断链清零**：{last_username}/{user_num}/{time} 及 [|] 随机段全链接线（2026-10-31 三批次）。

### 不足
1. **choreo_step_id 回退路径的固有模糊**：同内容重复触发且未透传实例号的极端场景仍可能误配/漏配（O9 声明为容差回退）——当前生产点已全部透传，风险收敛但未归零。
2. **未识别类型静默丢弃**：消息队列对未识别类型"队尾+满则丢弃"无计数观测——动态文案 type 断链（trends_copywriting）即此类问题的历史实例，修复靠审查而非机制。监听侧已有 `_BoundedDropQueue.dropped_count` 分类型计数（danmaku_consumer.py:88-118），主系统两级队列可照此模式落地（P-1）。
3. **礼物计价连击少计**：B站/快手连击语义与差值去重不匹配，修复依赖真实样本采集（TODOS 2026-10-22 弹幕批次 #3）。
4. **助播与数字人重叠无避让**：同刻重叠为已接受设计属性（D9），实播投诉成立再评估——精准维的已知取舍。
5. **语义矩阵漂移机制面（v2 新增，Low）**：A6 守卫只告警不阻断——webui 写未登记键仅日志告警，无测试断言强制补行；多批次并行在飞时矩阵行与代码可能短暂失配。登记为流程观察（告警+批次纪律在当前规模够用，不加阻断守卫）。

### 建议
- **P-1**：队列落"丢弃计数器"（按丢弃原因分桶：满载/未识别/999 舍弃/限入/去重），webui 状态条透出——把每次架构审查的"断链考古"变成运行期可见指标，精准维投入复利化最高的一项（参照监听侧 dropped_count 既有模式）。
- **P-2**：choreo_step_id 透传完整性加守卫测试（枚举全部入队生产点断言携带），防新增生产点退回容差匹配。
- **P-3**：连击样本采集（fixture）后做计数语义对齐，礼物计价直接影响答谢门槛与积分金额榜精度。
