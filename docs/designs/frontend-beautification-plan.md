## Problem Statement

当前 AUTOlive 前端的字体、字号、颜色等元素视觉效果不统一，各项参数的按钮位置、参数输入框布局、参数标题等都比较杂乱，需要进行美观方面的优化。

## Goals

- 统一的层级标题字体、颜色、字号
- 统一的按钮样式和界面布局
- 统一的输入框样式和布局
- 统一的参数标题字号、颜色和布局

## Current State Analysis

### Architecture
- 基于 NiceGUI 框架的 Python Web UI
- 模块化结构：`frontend/` 目录包含 styles、ui、utils、config
- 主题系统：`frontend/styles/themes.py` 管理浅色/深色模式
- 布局系统：`frontend/ui/layout.py` 的 `DrawerLayout` 类
- 组件系统：`frontend/ui/components/__init__.py` 的 `FormField` 类

### Identified Issues

1. **样式分散**：各 tab 文件中大量内联 `.style()` 调用，没有统一规范
2. **字体不统一**：标题有 18px、20px、24px 等多种大小
3. **按钮样式不一致**：有的用 `color=primary`，有的用内联 `background-color`
4. **输入框宽度不统一**：200px、300px、400px、500px 混用
5. **间距不一致**：padding 和 margin 值在各处不同
6. **卡片样式不统一**：有的有阴影，有的没有

## Scope

### In Scope
1. 创建统一的 CSS 变量系统（设计令牌）
2. 统一标题样式（h1-h4 级别）
3. 统一按钮样式（主要、次要、危险等）
4. 统一输入框样式和布局
5. 统一参数标题样式
6. 统一间距和卡片样式
7. 更新主题系统支持新的设计令牌

### NOT in Scope
- 功能变更
- 新增功能
- 配置数据结构变更
- 第三方框架替换

## Implementation Plan

### Phase 1: Design Tokens（设计令牌）
- 在 `frontend/styles/` 创建 design_tokens.py
- 定义颜色、字体、间距、圆角、阴影等变量
- 支持浅色/深色模式

### Phase 2: Global Styles（全局样式）
- 更新 `layout.py` 的 `inject_global_styles()`
- 注入统一的 CSS 变量
- 定义基础元素样式

### Phase 3: Component Styles（组件样式）
- 更新 `FormField` 组件样式
- 统一按钮样式
- 统一卡片样式

### Phase 4: Tab Updates（标签页更新）
- 更新各 tab 文件使用统一的样式类
- 移除内联样式
- 使用设计令牌

## Constraints
- 保持现有功能不变
- 使用 NiceGUI 框架
- 保持配置系统兼容性
- 支持主题切换

## Success Criteria
1. 所有标题使用统一的字体和大小
2. 所有按钮使用统一的样式
3. 所有输入框使用统一的宽度和样式
4. 所有参数标题使用统一的样式
5. 视觉效果整洁一致

## Design Review (Phase 2)

### Pass 1: Information Architecture — 8/10

**现状：** 已有 drawer 布局（左侧导航 + 二级功能列表 + 三级配置页面），信息层级清晰。
**差距：** 配置页面内部的信息层级未定义——标题、参数组、操作按钮的视觉权重不明确。
**修复：** 在计划中添加配置页面内部的视觉层级规范。

### Pass 2: Interaction State Coverage — 6/10

**现状：** 计划未指定交互状态。
**差距：** 缺少以下状态的视觉规范：
- 加载状态（配置加载中）
- 空状态（无配置项）
- 错误状态（配置加载失败）
- 成功状态（保存成功）

**修复：** 添加交互状态表：

| 功能 | 加载 | 空 | 错误 | 成功 |
|------|------|-----|------|------|
| 配置页面 | spinner + "加载中" | "暂无配置" | 红色错误提示 + 重试按钮 | 绿色通知 |
| 保存操作 | 按钮禁用 + "保存中" | — | 红色通知 | "配置已保存" |

### Pass 3: User Journey & Emotional Arc — 7/10

**现状：** 计划关注视觉统一，但未考虑用户情感体验。
**差距：** 用户打开配置页面时应感到"整洁、专业"，而非"杂乱、随意"。
**修复：** 设计令牌应传达"专业工具"的感觉——冷静的蓝色调、清晰的层级、适度的间距。

### Pass 4: AI Slop Risk — 9/10

**现状：** 这是一个设置应用，不是营销页面，AI slop 风险低。
**检查：**
- ❌ 紫色渐变背景？当前有 `#667eea` 到 `#764ba2` 渐变（导航栏标题区域）→ 需要替换
- ❌ 3列特性网格？不适用
- ✅ 卡片使用合理（配置分组）
- ✅ 无装饰性元素

**修复：** 将导航栏渐变替换为更专业的纯色或微妙渐变。

### Pass 5: Design System Alignment — 5/10

**现状：** 有 `DESIGN_TOKENS` 定义但未广泛使用。`themes.py` 有基础主题但不完整。
**差距：**
- 缺少统一的 CSS 变量系统
- 设计令牌定义在 Python 中，未注入为 CSS 变量
- 组件样式硬编码，未引用令牌

**修复：** 创建 `frontend/styles/design_tokens.py`，定义 CSS 变量并在全局注入。

### Pass 6: Responsive & Accessibility — 4/10

**现状：** 有基础响应式断点（768px, 576px），但未覆盖所有组件。
**差距：**
- 输入框宽度硬编码（200px-500px），小屏幕会溢出
- 未指定触摸目标大小
- 颜色对比度未验证

**修复：** 添加响应式输入框规范（使用百分比或 max-width），确保按钮最小 44px 触摸目标。
