# 技术栈选型

## 1. 核心决策 (Key Decisions)

### 为什么选择 Python？
- **AI 生态最丰富**：PyTorch、Transformers、LangChain 等核心库都是 Python 优先
- **快速原型开发**：项目需要快速迭代，Python 的开发效率最高
- **社区支持**：直播平台 SDK、TTS 引擎等大多提供 Python 接口
- **跨平台兼容**：虽然当前仅支持 Windows，但 Python 本身跨平台

### 为什么选择单体架构？
- **部署简单**：用户只需运行一个程序，无需配置微服务
- **配置统一**：所有功能通过一个 config.json 管理
- **适合场景**：面向个人用户，不需要高并发分布式架构

### 配置加载
```python
class Config:
    def __init__(self, config_file):
        with open(config_file, 'r', encoding="utf-8") as f:
            self.config = json.load(f)
    
    def get(self, *keys):
        result = self.config
        for key in keys:
            result = result.get(key, None)
        return result
```

## 14. 优化建议

### 🔴 高优先级优化

#### 1. 数据库连接管理
**问题**：每次查询创建新连接，性能差且不稳定
```python
# 当前实现（有问题）
def fetch_all(self, query, args=None):
    conn = sqlite3.connect(self.db_file)  # 每次新建连接
    cursor = conn.cursor()
    # ...
```

**建议**：使用连接池或 ORM
```python
# 方案 A：改进连接池
from contextlib import contextmanager

@contextmanager
def get_connection(self):
    conn = self.connection_pool.get()
    try:
        yield conn
    finally:
        self.connection_pool.put(conn)

# 方案 B：使用 SQLAlchemy
from sqlalchemy import create_engine
from sqlalchemy.orm import sessionmaker

engine = create_engine('sqlite:///data/data.db', pool_size=5)
Session = sessionmaker(bind=engine)
```

#### 2. 配置热更新
**问题**：修改配置需要重启程序
**建议**：实现配置文件监听和热重载
```python
from watchdog.observers import Observer
from watchdog.events import FileSystemEventHandler

class ConfigHandler(FileSystemEventHandler):
    def on_modified(self, event):
        if event.src_path.endswith('config.json'):
            self.reload_config()
```

#### 3. 异步化改造
**问题**：部分模块使用同步 IO，阻塞事件循环
**建议**：全面异步化
```python
# 当前（同步）
def get_response(self, prompt):
    response = requests.post(url, json=data)
    return response.json()

# 建议（异步）
async def get_response(self, prompt):
    async with aiohttp.ClientSession() as session:
        async with session.post(url, json=data) as resp:
            return await resp.json()
```

### 🟡 中优先级优化

#### 4. 日志结构化
**问题**：日志格式不统一，难以检索

```python
from loguru import logger
```

#### 5. 错误处理统一
**问题**：异常处理不一致，部分吞掉异常
**建议**：定义统一异常类
```python
class AutoliveException(Exception):
    """基础异常"""
    pass

class LLMException(AutoliveException):
    """LLM 调用异常"""
    pass

class TTSException(AutoliveException):
    """TTS 合成异常"""
    pass
```

#### 6. 测试框架
**问题**：缺少单元测试和集成测试
**建议**：引入 pytest

#### 8. 代码格式化
**建议**：统一使用 black + isort + ruff
```toml
# pyproject.toml
[tool.black]

[tool.ruff]
```

#### 9. 类型提示
**建议**：逐步添加类型提示
```python
# 当前
def get(self, *keys):
    result = self.config
    for key in keys:
        result = result.get(key, None)
    return result

# 建议
def get(self, *keys: str) -> Any:
    result: Any = self.config
    for key in keys:
        if isinstance(result, dict):
            result = result.get(key, None)
        else:
            return None
    return result
```

#### 10. 文档字符串
**建议**：统一 docstring 格式（Google 风格）

```python
    Returns:
        str: 模型生成的回复文本
        
    Raises:

    """
```
