# 实现计划：音频三项目整合（GPT-SoVITS / RVC / AICoverGen）

生成：2026-09-24 | 分支：main | 来源：/autoplan ARGUMENTS + 已批准设计文档 docs/designs/audio-integration-voice-pipeline.md

## 目标

把 D:\AI\GPT-SoVITS、D:\AI\RVC20240604Nvidia、D:\AI\AICoverGen 三个外部项目收编为 AUTOlive 系统功能：TTS 内部调度、实时变声（运行时热切换模型）、声音训练（数字人-训练声音）、一键翻唱（高级功能-点歌模式）。产品叙事：声音身份生产线——录音 → 训练声音模型 → 同一声音身份流入 TTS/变声/翻唱三端。

## 现状（代码核实）

- TTS：`utils/audio_handle/my_tts.py` HTTP 外部 API；`gpt_sovits` 配置指向 `127.0.0.1:9880`（外部管理，`type: "api"`）。
- 变声：`frontend/ui/tabs/svc.py` 配置旧 so-vits-svc 外部服务（`127.0.0.1:1145`，`enable=true` 已核实为启用态，指向 `E:\so-vits-svc`；CEO-F5：P2 开工前核实作者直播是否在用——在用则旧卡保留手动开启直至 P2-1 实测达标）。
- 点歌：`frontend/ui/tabs/choose_song.py` 本地音频相似度匹配，无翻唱。
- EDTalk 集成已建立范式：复制为唯一副本 + 子进程编排 + 配置驱动 UI + 步骤清单训练页 + GPU 占用检查。
- D:\AI\runtime312-clone 的 users.pth 已注入 6 个 GPT-SoVITS 路径（与 AUTOlive 内 edtalk/runtime312 目录重名歧义，后者仅含 ffmpeg；本计划 runtime312 均指前者）。

## 方案取舍（CEO-F9 留痕）

- 拒绝"现成一体化商业方案"：闭源 SaaS 不可自托管，声音身份资产不可控。
- 拒绝"继续外部进程+安装向导"：痛点正是运行时链路（启动顺序/崩溃恢复），向导不解决。
- 拒绝"仅做 TTS+训练两件套"：变声/翻唱属用户已验证需求面（"手动搭链路，很痛苦"覆盖三能力）。
- 详细对比见 docs/designs/audio-integration-voice-pipeline.md（方案 A/B/C）。

## 关键裁决（设计文档已定，计划照此执行）

1. GPT-SoVITS：AUTOlive 托管 api_v2 子进程（自动拉起/配置注入/健康检查），TTS 走内部调度（同机 HTTP 回环，生命周期由系统管理）。
2. RVC：**包裹式服务**——AUTOlive 自建薄推理服务（子进程 + 声音设备 I/O，复用 `tools/rvc_for_realtime.py` 推理类，版本锁定），支持运行时热切换（≤1s 静音间隙，流不中断；不支持则降级快速重启切换，P2 工程审查验证）。
3. 模型共享：仅建 `models/rvc/` 共享目录（RVC+AICoverGen）；GPT-SoVITS 权重族留在原目录。
4. 声音档案：config.json 新增 `voice_profiles` 节（档案 ID → GPT-SoVITS 模型对 + RVC 模型/index + 参考音频），三端选择器共用。
5. 环境策略默认案：GPT-SoVITS→runtime312；RVC 包裹服务→RVC 自带 runtime；AICoverGen→复用 RVC runtime 或独立 venv（P3 定）。
6. GPU 优先级：直播关键路径（EDTalk 推理/TTS/变声）> 背景任务（翻唱/训练）；探测条件 = 直播运行中 OR EDTalk 训练占用中 OR 显存余量 < 阈值（约 4GB）；命中时训练拒绝启动错峰、翻唱排队等待——两种处置为有意设计（训练不可中断故拒绝准入，翻唱轻量可中断故排队）；条件定义修正为"直播运行中（含 EDTalk 推理）OR EDTalk 训练占用中 OR 显存余量 < 阈值"，实现为单一 GPU 策略模块（is_background_task_allowed()，与 audio_integration.policies 同级），P2-3/P3-3 只消费不实现（E-2）。
7. 安装布局（CEO-F6 裁决）：装后磁盘布局 = AUTOlive 根下固定 apps/ 目录（apps/gpt-sovits、apps/rvc、apps/aicovergen，代码复制为唯一副本，与 EDTalk 范式一致）；模型/权重经根目录配置键指向共享位置。P1-2 与 P1-5 按此布局设计与打包。

## 设计规范（Design Review 裁决）

- 全部新 UI 使用 frontend/styles/design_tokens.py 令牌，禁止硬编码色值；宽度遵循三档规范。

- a11y：Quasar 基础 + 令牌对比度 + 表单 Tab 序；ARIA 增强沿用 TODOS 既有延期项。

## 验收标准（全期）

1. 真实用户双击安装包→开播出声 ≤30 分钟，无作者到场（允许一次驱动 UAC 提权确认，与 P1-5 口径一致）（P1）。
2. TTS 无外部手动服务依赖，托管生命周期含失控防护（P1）。
3. 变声热切换：流不中断 + ≤1s 静音间隙 + 端到端 ≤500ms（P2）；若触发快速重启降级则本条同步修订为"切换中断 ≤5s"并与 P2-1 验收口径一致。
4. 训练完成的声音以档案形式被三端直接选用（P2/P3）。
5. 翻唱异常路径有确定直播表现（P3）。
6. 北极星指标：作者被求助次数显著下降（口径：连续 3 次装机零远程协助）。护栏口径：装机后 7 天内故障求助次数；P3 开工数据门：若 P1/P2 未产生 ≥1 次零协助装机，P3（翻唱链）暂缓并复核。

## 风险

- R1: rvc_for_realtime.py 不支持进程内换模 → 降级快速重启切换（P2-1 验收口径相应修订）。
- R2: api_v2 运行中换模不确定 → 重启托管进程兜底（秒级 TTS 中断，可接受）。
- R3: 三项目依赖冲突 → 环境策略默认案隔离（P1 工程审查确认）。
- R4: GPU 显存不足以并行直播+训练 → GPU 优先级策略准入拒绝，训练错峰。
- R5: 商用许可（MIT 项目本体 vs 模型许可）、声音克隆授权、歌曲版权与平台 ToS（翻唱产物为受版权保护歌曲的演绎作品，直播回播有下架/账号风险）→ OQ3 核查清单（含歌曲版权节，CEO-F10），装机前完成许可+授权两项；P3 开工前裁决翻唱曲库范围（无版权/授权曲库优先或作者自备），功能文案加风险告知；作者直播有收益则默认从严；声音克隆授权机制商用前需从纸面升级为可验证绑定（录音哈希与授权记录关联，S-2 留痕）。
- R6: 安装包体积（底模数 GB）→ OQ5 按需选装。
