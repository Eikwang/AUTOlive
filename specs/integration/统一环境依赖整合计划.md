## 5. 版本冲突与风险提示（只定性，不锁版本）

1. **gradio 大版本分裂（最高风险）**：RVC 系 3.x、AI-Vtuber 系 4.x、GPT-SoVITS 6.x、AICoverGen 4/5.x。统一环境只能存在一个 gradio，四个 WebUI 不可能同时兼容。**这是需要用户拍板的方向性决策**（见第 7 节 D1）。
2. **pydantic 1.x vs 2.x**：AI-Vtuber 的 overrides.txt 锁 pydantic 1.x；runtime312 基线是 pydantic 2.x（gradio 4+/GPT-SoVITS 需要 2.x）。整合后 AI-Vtuber 相关代码需适配 pydantic 2 API（属于用户说的"后期逐个调用依赖版本 API 差异"范围）。
3. **numpy 2.x 基线**：runtime312 是 numpy 2.x，fairseq 0.12.x 等老包历史上与 numpy 2 有兼容问题，装好后需冒烟验证（RVC/AICoverGen 的 fairseq 链路）。
4. **torch 代差**：基线 torch cu128 明显新于 RVC 原 runtime 的 cu118/torch 2.0。RVC 老代码路径（尤其训练/推理入口）需冒烟验证；推理 API 大体向后兼容。
5. **Python 3.9 → 3.12**：RVC 原环境是 3.9，迁到 3.12 需检查语法/弃用 API（如 distutils 移除等）。
6. **opencv 三变体并存**：基线同时装了 opencv-python、opencv-contrib-python、opencv-python-headless，存在互相覆盖风险，整合后建议收敛为 contrib 一个。
7. **环境残留**：runtime312 有 `~riton`、`~ryptography` 残骸目录与 tb-nightly（ nightly 测试版 tensorboard）混装，建议清理。

## 6. 整合结构方案

- **主仓库**：AI-Vtuber（已有 .git，2308 提交），其余 5 项目以 `git submodule add` 接入——**前置条件见第 8.0 节**（3 个子项目 git 状态不合格，需先补齐）。
- **统一环境**：所有 Python 入口统一用 `D:\AI\EDTalk\runtime312\python.exe` 启动；启动脚本（各项目 .bat）逐个改写指向。
- **环境归属决定（CEO 声部发现 4 采纳）**：runtime312 是 conda 环境，**不可搬迁**（内部硬编码绝对路径），且物理上位于 EDTalk 仓库目录内。明确决定：① 环境保持原地不动；② 各仓库 .gitignore 必须覆盖 `runtime312/`，它**不进任何 git 管辖**，视为机器本地资产；③ 环境的 lock 快照（freeze 导出）归主仓库管理——环境本身可因 EDTalk 子模块变动而"无主"，但锁文件+重建说明随主仓库走；④ 禁止对 runtime312 做 `git clean -fdx` 类操作及移动/改名。
- **服务拓扑**：DanmakuListener(弹幕) → AI-Vtuber(中枢编排) → GPT-SoVITS(TTS) / RVC(变声) / AICoverGen(翻唱) / EDTalk(数字人驱动)，各服务独立端口，中枢经 HTTP API 调用（与现状一致，仅换解释器）。
- **本期不做**（用户明确留到后期）：依赖版本 API 差异适配、代码级合并、界面整合。
