# 开发规范

本文档定义 Luna AI (AUTOlive) 项目的代码风格、命名约定、Git 工作流和 AI 协作协议，确保代码库长期可维护。

## 1. 语言与运行时要求

| 维度 | 规格 |
|------|------|
| **语言** | Python 3.10+，全栈统一 |
| **运行时** | CPython 3.10.x（推荐 3.10.11） |
| **包管理器** | pip（推荐配合 conda 虚拟环境） |
| **类型提示** | 建议使用，不强制（逐步添加） |

## 3. 命名约定

### 3.1 文件与目录命名

| 类型 | 命名风格 | 示例 |
|------|---------|------|
| **模块文件** | `snake_case.py` | `my_handle.py`, `audio_player.py` |
| **目录** | `snake_case` | `gpt_model/`, `audio_handle/` |
| **配置文件** | `snake_case.json` | `config.json`, `本地问答库.json` |
| **测试文件** | `test_*.py` | `test_config.py` |
| **脚本文件** | `kebab-case.bat` 或描述性命名 | `1.双击我启动程序.bat` |

### 3.2 代码命名

| 元素 | 命名风格 | 示例 | 状态 |
|------|---------|------|------|
| **类** | `PascalCase` | `My_handle`, `Audio`, `Config` | ✅ 当前 |
| **函数** | `snake_case` | `get_resp()`, `handle_comment()` | ✅ 当前 |
| **变量** | `snake_case` | `config_path`, `audio_out_path` | ✅ 当前 |
| **常量** | `SCREAMING_SNAKE_CASE` | `MAX_RETRY_COUNT` | ⚠️ 建议 |
| **私有属性** | `_前缀` | `self._lock`, `self._instance` | ✅ 当前 |
| **布尔变量** | `is/has/should` 前缀 | `is_handleing`, `is_playing` | ✅ 当前 |
| **全局变量** | `my_` 前缀（项目特有） | `my_global`, `my_handle` | ✅ 当前 |

### 3.3 命名问题与修正

| 问题 | 当前写法 | 建议写法 | 说明 |
|------|---------|---------|------|
| 拼写错误 | `is_handleing` | `is_handling` | 英文拼写错误 |
| 风格不一致 | `My_handle` | `MyHandle` | 类名应全 PascalCase |
| 过度缩写 | `resp` | `response` | 保持可读性 |
| 中文命名 | `本地问答库.json` | `local_qa.json` | 配置文件建议英文 |

## 4. Python 特定规范

### 4.1 导入规范

```python
# ✅ 正确写法：按标准顺序导入
# 1. 标准库
import os
import sys
import json
import threading
from typing import Dict, List, Optional

# 2. 第三方库
import aiohttp
import pygame
from loguru import logger

# 3. 本地模块
from utils.config import Config
from utils.common import Common
from utils.audio_handle.my_tts import MY_TTS

# ❌ 错误写法：导入顺序混乱
from utils.config import Config
import os
import aiohttp
from utils.common import Common
```

### 4.2 类型提示

```python
# ✅ 推荐：关键函数添加类型提示
def get_response(self, prompt: str, model: str = "gpt-3.5-turbo") -> Optional[str]:
    """获取 LLM 回复"""
    pass

# ✅ 可接受：简单函数省略类型提示
def get_random_float(self, data):
    """获取随机浮点数"""
    pass

# ❌ 避免：返回类型不明确
def get_response(self, prompt):
    # 可能返回 str、None 或抛出异常
    pass
```

### 4.3 字符串格式化

```python
# ✅ 推荐：f-string（Python 3.6+）
logger.info(f"配置加载成功: {config_path}")
message = f"欢迎{username}来到直播间"

# ✅ 可接受：format 方法（兼容旧代码）
message = "欢迎{}来到直播间".format(username)

# ❌ 避免：% 格式化（可读性差）
logger.info("配置加载成功: %s" % config_path)
```

### 4.4 异常处理

```python
# ✅ 正确写法：捕获具体异常
try:
    response = requests.get(url, timeout=10)
    response.raise_for_status()
except requests.exceptions.Timeout:
    logger.error("请求超时")
    return None
except requests.exceptions.HTTPError as e:
    logger.error(f"HTTP 错误: {e}")
    return None
except requests.exceptions.RequestException as e:
    logger.error(f"请求异常: {e}")
    return None

# ❌ 错误写法：捕获所有异常
try:
    response = requests.get(url)
except Exception as e:
    logger.error(f"出错了: {e}")
    # 吞掉异常，导致问题难以排查

# ❌ 错误写法：空 except
try:
    response = requests.get(url)
except:
    pass
```

### 4.5 避免的写法

```python
# ❌ 避免 1：可变默认参数
def __init__(self, items=[]):  # 危险！
    self.items = items

# ✅ 替代方案
def __init__(self, items=None):
    self.items = items if items is not None else []

# ❌ 避免 2：魔法数字
if status == 3:  # 3 是什么意思？
    pass

# ✅ 替代方案
STATUS_ACTIVE = 3
if status == STATUS_ACTIVE:
    pass

# ❌ 避免 3：过长的函数（超过 100 行）
def handle_comment(self, ...):
    # 500 行代码...
    pass

# ✅ 替代方案：拆分为小函数
def handle_comment(self, ...):
    filtered_comment = self._filter_comment(comment)
    response = self._get_llm_response(filtered_comment)
    self._send_to_audio(response)
```

## 5. 项目架构规范

### 5.1 模块设计原则

- **单一职责**：每个模块只负责一个功能领域
- **依赖方向**：上层模块依赖下层模块，禁止反向依赖
- **接口抽象**：模块间通过接口交互，减少耦合

### 5.2 模块文件结构

```python
# -*- coding: UTF-8 -*-
"""
@Project : AUTOlive
@File    : module_name.py
@Author  : 作者名
@Email   : 邮箱
@Date    : YYYY/MM/DD
@Description : 模块功能描述
"""

# 1. 标准库导入
import os
import json

# 2. 第三方库导入
import aiohttp
from loguru import logger

# 3. 本地模块导入
from utils.config import Config

# 4. 常量定义
MAX_RETRY_COUNT = 3
DEFAULT_TIMEOUT = 60

# 5. 类定义
class ModuleClass:
    """模块类的文档字符串"""

    def __init__(self, config_path: str):
        """初始化方法"""
        self.config = Config(config_path)

    def public_method(self):
        """公共方法"""
        pass

    def _private_method(self):
        """私有方法"""
        pass
```

### 5.3 导入排序规则

```python
# 按以下顺序分组，组间空一行：
```

## 6. 日志规范

### 6.1 日志级别使用

| 级别 | 使用场景 | 示例 |
|------|---------|------|
| **DEBUG** | 调试信息，生产环境关闭 | `logger.debug(f"配置值: {value}")` |
| **INFO** | 关键业务流程 | `logger.info("TTS 合成完成")` |
| **WARNING** | 可恢复的异常 | `logger.warning("API 调用失败，使用备用方案")` |
| **ERROR** | 错误但不致命 | `logger.error(f"数据库查询失败: {e}")` |
| **CRITICAL** | 致命错误 | `logger.critical("配置文件损坏")` |

### 6.2 日志格式

```python
# ✅ 正确写法：包含上下文
logger.info(f"用户 {username} 发送弹幕: {comment}")
logger.error(f"TTS 合成失败，引擎: {engine}, 错误: {e}")

# ❌ 错误写法：缺少上下文
logger.info("处理完成")
logger.error("出错了")
```

### 6.3 异常日志

```python
# ✅ 正确写法：记录完整堆栈
try:
    result = some_operation()
except Exception as e:
    logger.error(f"操作失败: {e}")
    logger.error(traceback.format_exc())

# ❌ 错误写法：只记录错误消息
try:
    result = some_operation()
except Exception as e:
    logger.error(f"出错了: {e}")
    # 缺少堆栈信息，难以排查
```

## 8. Git 工作流

### 8.1 分支策略

> 项目为个人开发者为主，采用简化 Trunk-Based 策略

```
main (主分支，始终可部署)
  │
  ├── feat/xxx (功能分支)
  ├── fix/xxx (修复分支)
  └── refactor/xxx (重构分支)
```

| 规则 | 说明 |
|------|------|
| **主分支** | `main`，始终可部署 |
| **功能分支** | 从 `main` 创建，完成后合并回 `main` |
| **分支生命周期** | 1-3 天，避免长期分支 |
| **合并方式** | Squash Merge（保持历史清晰） |

### 8.2 分支命名规范

```
<type>/<short-description>
```

| 类型 | 用途 | 示例 |
|------|------|------|
| `feat/` | 新功能 | `feat/tiktok-platform` |
| `fix/` | Bug 修复 | `fix/audio-playback-error` |
| `refactor/` | 重构 | `refactor/my-handle-split` |
| `docs/` | 文档更新 | `docs/api-spec` |
| `chore/` | 构建/配置 | `chore/update-deps` |

### 8.3 提交信息规范 (Conventional Commits)

所有 Git 提交信息**必须**遵循 Conventional Commits 格式：

```
<type>(<scope>): <subject>

[body]

[footer]
```

#### 类型 (type)

| 类型 | 说明 | 示例 |
|------|------|------|
| `feat` | 新功能 | `feat(platform): 添加抖音直播支持` |
| `fix` | Bug 修复 | `fix(audio): 修复 TTS 合成超时问题` |
| `refactor` | 重构（不改变功能） | `refactor(handle): 拆分 my_handle 模块` |
| `style` | 代码格式调整 | `style: 统一代码缩进风格` |
| `docs` | 文档变更 | `docs: 更新 README 安装说明` |
| `test` | 测试相关 | `test: 添加配置模块单元测试` |
| `chore` | 构建/工具/依赖 | `chore: 升级 aiohttp 到 3.9` |
| `perf` | 性能优化 | `perf(audio): 优化音频队列处理` |

#### 作用域 (scope)

| scope | 对应范围 |
|-------|---------|
| `platform` | 直播平台相关 |
| `llm` | AI 模型相关 |
| `tts` | 语音合成相关 |
| `audio` | 音频处理相关 |
| `config` | 配置管理相关 |
| `ui` | Web UI 相关 |
| `game` | 游戏模块相关 |

#### 提交信息示例

```
feat(platform): 添加快手直播平台支持

- 实现快手 WebSocket 弹幕监听
- 支持礼物和入场事件处理
- 添加快手礼物价格表配置

Closes #123
```

```
fix(audio): 修复 GPT-SoVITS 合成超时问题

增加重试机制和超时配置，解决网络不稳定时合成失败的问题。

根因：默认 60s 超时在网络波动时不够用
```

## 10. 错误处理规范

### 10.1 异常分类

```python
# 定义项目异常层次
class AutoliveException(Exception):
    """项目基础异常"""
    pass

class ConfigException(AutoliveException):
    """配置相关异常"""
    pass

class LLMException(AutoliveException):
    """LLM 调用异常"""
    pass

class TTSException(AutoliveException):
    """TTS 合成异常"""
    pass

class PlatformException(AutoliveException):
    """平台连接异常"""
    pass
```

### 10.2 错误处理原则

```python
# ✅ 正确写法：分层处理
def handle_comment(self, username: str, comment: str):
    """处理弹幕"""
    try:
        # 1. 过滤
        filtered = self._filter_comment(comment)
        if not filtered:
            return
        
        # 2. 获取回复
        response = self._get_response(filtered)
        
        # 3. 合成音频
        self._synthesize_audio(response)
        
    except LLMException as e:
        logger.error(f"LLM 调用失败: {e}")
        # 使用备用回复
        response = "抱歉，我现在无法回答这个问题"
        self._synthesize_audio(response)
        
    except TTSException as e:
        logger.error(f"TTS 合成失败: {e}")
        # 记录错误，但不中断流程
        
    except Exception as e:
        logger.error(f"处理弹幕异常: {e}")
        logger.error(traceback.format_exc())
```

### 10.3 安全原则

- **永远不在 UI 中暴露原始错误堆栈**
- **永远不暴露数据库错误信息给用户**
- **永远不暴露 API 密钥或内部路径**

## 14. AI 协作协议

> 本节定义 AI 辅助开发时必须遵守的规则，确保 AI 生成的代码与人工代码保持一致性。

### 14.1 AI 写代码前必读

| 文档 | 路径 | 目的 |
|------|------|------|
| 产品概述 | `specs/产品概述.md` | 理解业务需求 |
| 技术栈 | `specs/技术栈.md` | 确认技术选型 |
| 项目结构 | `specs/项目结构.md` | 理解模块划分 |
| 开发规范 | `specs/开发规范.md` | 遵循代码风格 |
| 相关模块代码 | `utils/*.py` | 理解现有实现 |

### 14.2 AI 写代码的规则

| 规则 | 说明 |
|------|------|
| **读后写** | 修改文件前必须先读取该文件 |
| **最小改动** | 只修改任务要求的部分，不做"顺便优化" |
| **不猜版本** | 安装依赖时使用包管理器获取最新版，不手写版本号 |
| **不引入新依赖** | 除非任务明确要求 |
| **不写无意义注释** | 不写复述代码的注释 |
| **不创建多余文件** | 不主动创建文档或配置文件 |
| **遵循现有模式** | 相同类型的代码必须遵循已有文件的写法 |
| **错误处理** | 必须捕获具体异常，不能使用 `except Exception` |
| **日志记录** | 关键操作必须记录日志 |

### 14.3 AI 写完代码后必做

| 步骤 | 操作 | 命令 |
|------|------|------|
| **1. 语法检查** | 确认无语法错误 | `python -m py_compile file.py` |
| **2. Lint 检查** | 确认无 Lint 错误 | `ruff check file.py` |
| **3. 导入检查** | 确认导入顺序正确 | `ruff check --select I file.py` |
| **4. 依赖方向** | 确认没有违反依赖方向 | 手动检查 |

### 14.4 错题本机制

当 AI 生成的代码出现问题时，在 `specs/errata.md` 中记录：

```markdown
## [日期] 错误类型

**错误描述**：具体出了什么问题

**根因分析**：为什么会犯这个错

**正确做法**：下次应该怎么做

**相关文件**：涉及的文件路径
```

## 15. 目录依赖方向（速查）

```
┌─────────────────────────────────────────────────────────────┐
│                         main.py                             │
│                         webui.py                            │
└───────────────────────────┬─────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────────┐
│                     utils/my_handle.py                      │
│                     utils/audio.py                          │
└───────────────────────────┬─────────────────────────────────┘
                            │
            ┌───────────────┼───────────────┐
            │               │               │
            ▼               ▼               ▼
    ┌──────────────┐ ┌──────────────┐ ┌──────────────┐
    │  gpt_model/  │ │audio_handle/ │ │  platforms/  │
    └──────────────┘ └──────────────┘ └──────────────┘
            │               │               │
            └───────────────┼───────────────┘
                            │
                            ▼
                    ┌──────────────┐
                    │    common    │
                    │    config    │
                    │    my_log    │
                    └──────────────┘
```

**禁止方向**：
- `common` ✗→ `my_handle`（底层不能依赖上层）
- `config` ✗→ `audio`（配置层不能依赖业务层）
- `platforms` ✗→ `gpt_model`（同级模块不能互相依赖）
